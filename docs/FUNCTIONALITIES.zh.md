## 1. 指标

一共有八项指标可以显示，菜单里的「显示数据」逐项勾选；隐藏的项不占任何空间——那一行消失，面板随之变窄。

| 指标 | 显示什么 | 数据来自 |
| --- | --- | --- |
| 上传 / 下载 | 当前网速（上行、下行） | `sysinfo` 网卡累计字节差分 |
| CPU | 所有核心的总占用率 | `sysinfo` |
| 温度 | CPU 温度（AMD 上为封装 / Tctl） | PawnIO 驱动，退路是 LibreHardwareMonitor |
| 内存 | 已用物理内存占总内存的百分比 | `sysinfo` |
| GPU | 显卡占用率 | NVIDIA NVML |
| 显存 | 已用显存 | Windows GPU 性能计数器，退路是 NVML |
| GPU温 | 显卡温度 | NVIDIA NVML |

**网速只统计物理网卡。** loopback、虚拟网卡、VPN 隧道和蓝牙连接会按名称过滤掉，所以开着代理也不会让数字虚高。

**显存包含借用部分。** 这个数字是设备级的 committed 用量：专用显存 **加上** GPU 从系统内存借用的部分。所以它合法地可以超过 100 %，而正是这种情形值得注意——它意味着 GPU 自己的显存已经用满，正在往系统内存里溢，代价是带宽和帧时间。NVML 只报专用部分，数学上永远不可能超过 100 %，因此只作为性能计数器不可用时的退路（非 NVIDIA 显卡就属于这种情况）。

**GPU 占用与 GPU 温度是仅有的两项需要 NVIDIA 显卡的指标**，它们来自 NVML（驱动自带的库）。其余指标（含显存）在任何显卡上都可用；这两项在别处显示 `--`。

**CPU 温度是唯一需要提权的指标。** Windows 没有公开 API：数值在 MSR（Intel）或 SMN（AMD）寄存器里，只能在 ring 0 读取。装了 PawnIO 内核驱动时由它读取，否则退回到向正在运行的 LibreHardwareMonitor 发 HTTP 请求（端口 `lhm_port`）。

**数值越过阈值就变红**：温度 > 80 °C、内存 > 80 %、显存 > 100 %。名称列保持灰色，让数值继续承担视觉主位；除此之外没有任何颜色变化。

**未知即 `--`，绝不用 `0` 冒充。** 每个指标在内部都是可选的。读不到的值显示 `--`，而不是一个看起来像真实数据的零——这也解释了为什么空闲的网速显示 `0.00 B/s`（这是真实测量）而传感器缺失时显示 `--`。

**刻意不做的：** 磁盘 I/O、风扇转速、电压、单核占用、任何按进程的数据、以及任何形式的历史曲线。这些要么需要驱动或常驻服务，要么会让采样面比上面这几个轻量来源大得多。

## 2. 面板

### 2.1 布局

- **三种排列。** *竖排*每行一项（默认）。*横排*所有指标排成一行，名称在上、数值在下。*竖两排*每行两项，顺序为 上传/下载、CPU/温度、内存/GPU、显存/GPU温。
- **两种间距。** *紧凑*（默认）行间 1 个逻辑像素，*宽松* 2 个。只影响行间距，列间距始终紧凑。
- **对齐** —— 左（默认）、居中、右 —— 作用于每个单元格内的名称与数值，所以右对齐时整个面板读起来像一张表。
- **宽度固定，按最坏情况预留。** 名称列取可见标签中最宽的，数值列取每个可见指标**可能出现的最宽值**（`999.9 MB/s`、`100 %`、`100 °C`），都用实际字体的 `GetTextExtentPoint32W` 量出来。因此宽度取决于**显示哪些指标**和语言，**不取决于实时数据**：数字跳动永远不会让面板变大、变小或抖动，数值也永远不会被裁掉。
- **对齐是按单元格的**，所以在横排布局里名称和数值共用一列，彼此保持居中对齐。

### 2.2 尺寸与位置

- **DPI 感知。** 进程在任何窗口创建之前就声明 per-monitor-v2 DPI 感知。因此 Windows 永远不会把面板位图整体拉伸——内部一切都按原生像素尺寸绘制——并且窗口跨到缩放不同的显示器时会整体重算，让面板在任何显示器上保持相同的物理尺寸。
- **缩放。** 布局缩放为 `显示器 DPI / 96 × scale_percent / 100`。`100 %` 完全跟随 Windows 的显示缩放；菜单在此之上提供 50 / 75 / 100 / 125 / 150 / 175 %，配置文件接受 25–400。

  | `scale_percent` | 在 100 % 桌面上 | 在 150 % 桌面上（本项目的开发机） |
  | --- | --- | --- |
  | 50 % | 0.50× | 0.75× |
  | 100 % | 1.00× | 1.50× |
  | 150 % | 1.50× | 2.25× |
  | 175 % | 1.75× | 2.63× |

  所有由缩放推导的量一起变化：字号（名称 12 / 数值 14 逻辑像素，在 150 % 下成为 18 / 21 物理像素）、行高、边距、名称↔数值间距（以印刷点定义，因此始终是物理 2pt）、圆角半径，以及预留的列宽。
- **保持在屏内**（默认开启）。整个面板被限制在所属显示器内，而不只是左上角：
  - 拖动时停在边缘，而不是滑出屏幕；
  - 变大之后（提高缩放或显示更多指标）；
  - 窗口移到另一台显示器之后；
  - 启动时——因为保存的位置到那时可能已经过时（面板可能变大了，或者显示器排列变了）。
  面板只会被*移动*，从不改变尺寸；比显示器还大时贴左上角，而不是被两个约束来回推。关掉该设置即可恢复自由摆放（包括故意停一半在屏幕外）；托盘图标始终可达，所以任何状态下都有路可回。
- **拖动**：按住左键移动面板，松手立即写入新位置，所以位置能扛住崩溃，而不只是正常退出。

### 2.3 外观

- **六档透明度**：30 / 45 / 60 / 72（默认）/ 85 / 100 %。只有面板背景是半透明的——文字始终以完全不透明合成，这正是 30 % 时在明亮壁纸上数字依然可读的原因。
- **颜色。** 指标名是灰色（`#C0C0C0`）；数值为白色，越过阈值后变红（`RGB 255,80,80`）。背景是配置了对应 alpha 的黑色。
- **字体**是 Microsoft YaHei，字重 600，按缩放后的像素尺寸创建，因此中英文由同一字体渲染，任何缩放下都锐利。
- **形状**：带逐像素 alpha 的圆角矩形（半径 10 逻辑像素，150 % 下为 15 物理像素），没有边框、没有阴影、没有出现动画。
- **语言**：中文或 English，首次运行按 Windows 显示语言选择，之后随时可在菜单切换。只有标签会变；切换后面板会重新测量，因为中文标签比英文窄。

## 3. 菜单与托盘

右键菜单与托盘菜单是同一个菜单，由同一份代码一次构建，因此不可能出现两者不一致。托盘版本存在的意义，是让面板在被隐藏或停在屏幕外时仍然可以被找回和配置。

| 菜单项 | 可选值 | 作用 |
| --- | --- | --- |
| **显示数据** ▸ | 每项一个勾 | 开关该项指标；面板立即重新测量并改变尺寸 |
| **布局** ▸ | 竖排 / 横排 / 竖两排 | 切换排列 |
| **间距** ▸ | 紧凑 / 宽松 | 行与行之间的垂直间距 |
| **对齐** ▸ | 左 / 居中 / 右 | 单元格内名称与数值的对齐 |
| **透明度** ▸ | 30 / 45 / 60 / 72 / 85 / 100 % | 背景不透明度 |
| **缩放** ▸ | 50 / 75 / 100 / 125 / 150 / 175 % | 在显示器缩放比例之上相乘 |
| **语言** ▸ | 中文 / English | 切换所有标签 |
| **保持在屏内** | 勾选 | 把面板锁在所属显示器内 |
| **开机自启** | 勾选 | 创建或删除登录计划任务 |
| **显示 / 隐藏** | — | 隐藏面板；采集继续 |
| **退出** | — | 退出并释放单实例锁 |

每次改动都会立刻写入配置文件，两个菜单的勾选状态也当场重建。

**「显示 / 隐藏」只是隐藏，不结束进程。** 采集继续运行，所以再次显示时面板立刻是最新数据，托盘图标也一直在。这也意味着隐藏的面板依然有第 6 节的那份开销。

## 4. 配置文件

所有设置都在一个文件里：`%APPDATA%\deskpulse\config.toml`。

- **没有任何改动就不会写文件。** 全新安装时并不存在这个文件；第一次点击菜单（或拖动）时才带着当前值创建它。
- **菜单每次改动都会重写文件**，所以手工编辑最好在悬浮窗关闭时进行——否则下一次点击就会覆盖掉。
- **读到超出范围的数值时会夹到合法区间**，并把夹取后的值写回文件，因此一个手误既不会产生不可用的面板，也不会让它启动不了。

| 字段 | 类型 / 取值 | 含义 |
| --- | --- | --- |
| `layout` | `vertical`（默认）/ `horizontal` / `grid` | 排列方式 |
| `spacing` | `tight`（默认）/ `loose` | 行间距 |
| `align` | `left`（默认）/ `center` / `right` | 单元格对齐 |
| `position` | `[x, y]`，物理像素 | 左上角坐标；拖动时写入 |
| `keep_on_screen` | `true`（默认）/ `false` | 面板是否限制在所属显示器内 |
| `refresh_secs` | 整数，默认 `1` | 采集间隔（秒）。**没有菜单入口** |
| `opacity` | `0.0`–`1.0`，默认 `0.72` | 背景不透明度；菜单提供六档，字段接受任意值 |
| `scale_percent` | 整数 25–400，默认 `100` | 在显示缩放之上叠加的界面缩放 |
| `autostart` | `true` / `false` | 与登录计划任务的状态对应 |
| `lhm_port` | 整数，默认 `8085` | LibreHardwareMonitor 的 HTTP 端口，仅作温度退路。**没有菜单入口** |
| `language` | `zh` / `en`，或留空 | 留空表示「下次启动时按 Windows 显示语言选择」 |
| `visible` | `true` / `false` 的子表 | 每项指标一个开关，键为 `net_up`、`net_down`、`cpu`、`cpu_temp`、`mem`、`gpu`、`vram`、`gpu_temp`；缺省为显示 |

其中 `refresh_secs` 和 `lhm_port` 没有菜单入口，只能改文件。例如改成每两秒采样一次，并把退路温度源指向另一个端口：

```toml
refresh_secs = 2
lhm_port = 8086
```

*（`refresh_secs` 是整数秒，1 是实际可用的最小值。）*

再例如只显示 CPU 与内存：

```toml
[visible]
net_up = false
net_down = false
cpu = true
cpu_temp = false
mem = true
gpu = false
vram = false
gpu_temp = false
```

由旧版本写在改名之前目录（`%APPDATA%\desk-stats`）里的配置，会在首次运行时被认领一次，随后写入新位置。

## 5. 启动、提权与登录任务

- **每个登录会话只允许一个实例。** 具名互斥量守着进程；第二次启动会安静退出，而不会画出第二个面板。
- **直读 CPU 温度需要管理员权限**，这是 PawnIO 设备的限制。正常启动时 deskpulse 会通过 UAC 重新启动自己。这个提示每次启动出现一次，而不是每次开机。
- **开机自启任务可以避开这个提示。** 「开机自启」会创建一个名为 `deskpulse`、`RunLevel Highest` 的登录计划任务。它不经 UAC 提示即以提权方式运行——这也是为什么即使你习惯手动启动，也值得开启自启。取消勾选会删除该任务。
- **其余功能在非提权下都能工作。** 如果关掉提权提示，悬浮窗照常运行：CPU 温度退到 LibreHardwareMonitor（或 `--`），其余七项指标不受影响。
- **这个任务是它唯一对系统做的改动。** 没有服务、不自行安装驱动（PawnIO 需要另外下载）、没有注册表键、没有 shell 钩子。

## 6. 性能

**测量背景。** 开发机，除悬浮窗外桌面空闲，显示 6 项指标，每秒采样一次，Windows 11 且显示缩放为 150 %——最后这一点有影响，因为缩放越大，位图和字体就越大。

| | |
| --- | --- |
| 处理器 | AMD Ryzen 5 9600X（6 核 / 12 线程） |
| CPU 占用 | **约 0.29% 单核**（约占整机 CPU 的 0.02%） |
| 私有内存 | **约 27 MB** |
| 工作集 | 约 43 MB |
| `deskpulse.exe` | **1.05 MB** |
| 线程 / 句柄 | 4–7 / 约 290 |

**怎么读这些数字。** *CPU 占用*是每秒消耗的 CPU 时间：0.29% 单核约等于**每秒 3 毫秒**——相当于动画界面渲染一帧的量级，只不过摊在一整秒里。*私有内存*是只属于该进程的内存（约 27 MB，主要是运行时和 GDI 对象）。*工作集*是进程常驻内存的总量，包含与系统共享的部分——数值更大，也是任务管理器默认显示的那一列。

**为什么这么低。**

- **数据不变就不重绘。** 采集线程每采到一份新快照才发消息唤醒窗口（默认每秒一次），窗口只在此时重绘，其余时间什么都不做。没有渲染循环、没有动画，也没有基于定时器的重绘。
- **整个面板就是一张小位图。** 背景、圆角和文字都被合成到内存里一张约 160×180 像素的 32 位 DIB 上——纯 CPU 工作——再用一次 `UpdateLayeredWindow` 交给合成器。每次刷新只有一次缓冲分配、一次调用。
- **完全不用 GPU API。** 界面不碰 OpenGL、Direct3D 或 Vulkan。这正是它能在只有 Microsoft 基本显示适配器的机器、虚拟机和远程桌面上运行的原因，也是它不与游戏抢 GPU 时间的原因。

**对比：** 同一悬浮窗此前的 `egui` / `wgpu` 构建工作集约 125 MB（OpenGL 后端）和 420 MB（WARP 后端），CPU 高一个数量级。原因不是那些框架不好，而是它们每帧都渲染，并为了画一个矩形和五行文字而引入整套 GPU API；手工画一张小 DIB 两件事都不做。

**什么会让开销变大。** CPU 大致随 `1 / refresh_secs` 上升（每秒两次采样就是两倍的采集工作），也随可见指标数量上升。内存随面板**面积**增长，所以同样的指标在更大的 `scale_percent` 下更费。这些绝对值都不高，但「每秒两次采样、175 % 下显示八项指标」并不是上表所描述的那套配置。

## 7. 打包与分发

**构建单文件：**

```powershell
cargo build --release
Copy-Item .\target\release\deskpulse.exe .\dist\deskpulse.exe
```

`target\release\deskpulse.exe` 就是完整成品：一个约 1 MB 的可执行文件，没有安装程序、没有附带 DLL、没有需要安装的运行时。`dist\deskpulse.exe` 只是日常部署用的副本；直接从 `target\release` 运行效果完全相同。可以拷到任何地方——U 盘、另一台机器、别的目录——双击即可运行。

**里面固定嵌入了什么，以及为什么：**

| 项目 | 做法 | 意义 |
| --- | --- | --- |
| 应用图标与版本信息 | `build.rs` 用 `winresource` 处理 `assets/icon.ico` | 资源管理器、任务管理器和文件属性里都能正确显示 |
| 不依赖 VC++ 运行时 | `.cargo\config.toml` 对 `x86_64-pc-windows-msvc` 开启 `+crt-static` | C 运行时被静态链接进来，干净的 Windows 装上就能直接跑 |
| 体积小 | release 档：`lto`、`codegen-units = 1`、`strip`、`panic = "abort"` | 链接时优化配合单编译单元，让优化器看到整个程序；strip 与 abort-on-panic 去掉调试信息和栈展开表 |
| 无控制台窗口 | `#![cfg_attr(not(debug_assertions), windows_subsystem = "windows")]` | GUI 子系统程序：双击时不会闪出一个黑框。debug 构建保留控制台，供 `--dump` 使用 |
| 诊断模式 | `deskpulse.exe --dump` | 不打开窗口，打印 5 次采样后退出；输出写到启动它的那个控制台 |

**重新生成图标**（只有改了图稿才需要）：

```powershell
pwsh -File .\assets\make-icon.ps1
```

**卸载**就是把上面的事情反过来：从菜单退出，取消勾选「开机自启」（或执行 `schtasks /Delete /TN deskpulse /F`），删掉 exe；如果要连设置一起清掉，再删除 `%APPDATA%\deskpulse`。

## 8. 需求与限制

- **Windows 10/11，64 位。** 在 Windows 11 x64 上构建和测试；所用 API 自 Windows 10 1703 起可用。
- **不依赖任何 GPU API**，也不需要 GPU 驱动——除了可选的 NVIDIA 驱动支撑那两项指标，见第 1 节。
- **管理员权限**只在直读 CPU 温度时需要；没有它，这一项会退到 LibreHardwareMonitor，否则显示 `--`。
- **多 GPU。** 占用与温度取自 0 号适配器（NVML）；显存取自性能计数器中专用占用最大的那个适配器——通常正是跑游戏的那块。
- **独占全屏游戏无法叠加显示，而且不是所有「全屏」都一样。** 面板是逐像素透明的分层窗口，只有经过 DWM 合成才存在。**真·独占全屏**（Windows 标记为 `QUNS_RUNNING_D3D_FULL_SCREEN` 的状态）会把显示器从桌面手上拿走，并让 DWM 停止合成那块屏。此时任何没有注入游戏进程的东西都画不上去：任务管理器勾了「置于顶层」也一样不可见，Windows 自己的音量条也不显示。所有能在其上显示数字的工具（RTSS / MSI Afterburner、Steam、Discord、WeGame 的浮窗）都是把 DLL 注入游戏、hook 它的 Present、在游戏自己那一帧里绘制；deskpulse 不做注入，因为这类游戏的反作弊会拦截注入并存在封号风险。
  - **能显示：** 黑神话：悟空（UE5 / DX12）与 Apex（`r5apex_dx12.exe`，DX12）。DX12 的「全屏」实际上仍是 DWM 合成的无边框窗口——实践中 DX12 没有真独占模式——所以面板照常可见。
  - **不能显示：** 英雄联盟（走老的 D3D9 真独占路径）与瓦洛兰特（安装配置为独占全屏）。这两种模式下画面里确实没有面板；把游戏改成「无边框」或「窗口」就能恢复。
- **尚未实现：** 历史曲线、会话日志、带实时数值的托盘提示、按游戏自动切换设置，以及中英以外的语言。

## 9. 诊断与磁盘文件

| 路径 | 内容 |
| --- | --- |
| exe 本身 | 运行所需的一切；它是便携的，放哪都行 |
| `%APPDATA%\deskpulse\config.toml` | 所有设置（第 4 节）；第一次改动时创建 |
| `%APPDATA%\deskpulse\diag.log` | 诊断信息：启动、DPI 感知、窗口与钩子创建、托盘状态、温度后端，以及任何错误（`UpdateLayeredWindow` 失败、前台钩子缺失） |

`diag.log` 每次启动时被清空，运行期间追加；当出现异常——面板没出现、托盘菜单不见了、温度后端退化——它是最先该看的地方。

命令行只有一个开关 `--dump`：启动采集器，把五行指标打印到启动它的控制台，然后退出。它不打开窗口，也不干扰正在运行的实例，因此是检查某台机器上某个指标是否正常的最快方式。
