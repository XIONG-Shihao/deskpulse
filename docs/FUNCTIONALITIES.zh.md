# deskpulse — 功能说明

[English](../FUNCTIONALITIES.md) | 中文

悬浮窗功能的完整说明。简介见 [README.zh.md](README.zh.md)，技术栈、架构与设计取舍见 [ARCHITECTURE.zh.md](ARCHITECTURE.zh.md)。

## 指标

- **上传 / 下载** —— 当前网速，只统计物理网卡：loopback、虚拟网卡与 VPN 都会被过滤掉。
- **CPU** —— 总占用率；**温度** 是 CPU 温度（封装 / Tctl）。
- **内存** —— 已用物理内存占比。
- **GPU / GPU温** —— 显卡占用率与温度（NVIDIA，走 NVML）。
- **显存** —— 已用显存，取自 GPU 性能计数器。

**显存包含借用部分。** 这个数字是设备级的 committed 用量——专用显存 **加上** GPU 从系统内存借用的部分——因此它合法地可以超过 100 %；作为退路的 NVML 纯专用口径永远不可能超过。这是刻意的：">100 %" 恰恰是值得注意的状态。

**数值越过阈值就变红**：温度 > 80 °C、内存 > 80 %、显存 > 100 %。名称列保持灰色，让数值继续承担视觉主位。

**未知即 `--`，绝不用 `0` 冒充。** 每个指标内部都是可选的；读不到的值显示为 `--`，而不是一个看起来合理的零。GPU 占用与温度需要 NVIDIA 驱动；其余指标（含显存）在任何显卡上都可用。

## 面板

### 布局

- **三种排列**：竖排（每行一项）、横排（一行所有项）、竖两排（每行两项，默认依次为 上传/下载、CPU/温度、内存/GPU、显存/GPU温）。
- **两种间距**：紧凑 / 宽松 —— 控制行与行之间的垂直间距。
- **对齐**：左 / 居中 / 右，作用于每个单元格内的名称与数值。
- **宽度固定，按最坏情况预留。** 名称列取可见标签中最宽的，数值列取每个可见指标**可能出现的最宽值**（`999.9 MB/s`、`100%`、`100°C`），都用实际字体的 `GetTextExtentPoint32W` 量出来。宽度只随「显示哪些指标」和语言变化，不随数据变化，所以数值跳动时面板既不增长也不抖动。
- **指标可选**：隐藏一项就少一行，面板随之变窄。

### 尺寸与位置

- **DPI 感知。** 进程声明 per-monitor-v2 DPI 感知，Windows 不会把窗口位图整体拉伸；面板和字体按显示器原生像素网格排布，窗口跨到缩放不同的显示器时会整体重算。
- **缩放。** 布局缩放为 `显示器 DPI / 96 × scale_percent / 100`。`100 %` 完全跟随 Windows 的显示缩放；菜单在此之上提供 50/75/100/125/150/175 %：在 150 % 的桌面上选 `150 %` 等于 100 % 桌面的 2.25 倍，选 `50 %` 则是四分之三。字体、行高、边距、圆角半径、预留列宽一起缩放；配置文件里的 `scale_percent` 接受 25–400。
- **保持在屏内。** 默认开启：整个面板留在所属显示器内——拖动时、放大后、跨到另一台显示器时、以及启动时（那时保存的位置可能已经过时）。只会移动、从不改变尺寸；比显示器还大时贴左上角。关掉它就可以把面板停一半在屏幕外。
- **拖动**：按住左键即可移动，松手即保存位置。

### 外观

- **六档透明度** —— 30 / 45 / 60 / 72（默认）/ 85 / 100 %。只有背景是半透明的，文字始终以完全不透明绘制，因此每一档都清晰可读。
- **速率格式**：整数部分最多 3 位、小数 1 位（`999.9 KB/s`）；不足一个单位时 2 位小数（`0.98 KB/s`）；需要 4 位整数时进位到下一单位（`1023.9 KB/s` → `1.00 MB/s`）。
- **语言**：中文或 English，首次运行按 Windows 显示语言选择，之后随时可切换。

## 菜单与托盘

右键菜单与托盘图标打开的是同一个菜单，由同一份代码构建，因此两者永远不会不一致。菜单项本身列在 README 的[界面](README.zh.md#界面)一节里，这里补充两点：

- **显示 / 隐藏**只是把面板藏起来，不结束进程——采集继续，随时可以立刻显示回来。
- **托盘图标始终可用**，即使面板被隐藏或停在屏幕外——它是从任何状态恢复的入口。

## 配置文件

设置存放在 `%APPDATA%\deskpulse\config.toml`。菜单每次改动都会重写该文件，所以手工编辑最好在悬浮窗关闭时进行；读到超出范围的数值时会被夹到合法区间。

| 字段 | 含义 |
| --- | --- |
| `layout` | `vertical`、`horizontal` 或 `grid`（竖两排） |
| `spacing` | `tight`（默认）或 `loose` |
| `align` | `left`（默认）、`center` 或 `right` |
| `position` | 左上角坐标（物理像素），拖动时写入 |
| `keep_on_screen` | `true`（默认）把整个面板限制在所属显示器内 |
| `refresh_secs` | 采集间隔（秒）—— 没有菜单入口 |
| `opacity` | 背景不透明度 0.0–1.0；菜单提供六档，字段接受任意值 |
| `scale_percent` | 界面缩放百分比，25–400；`100` 跟随 Windows 显示缩放 |
| `autostart` | 与登录计划任务对应 |
| `lhm_port` | LibreHardwareMonitor 的 HTTP 端口，仅作温度退路 —— 没有菜单入口 |
| `language` | `zh` 或 `en`；留空则下次启动时按系统语言自动选择 |
| `visible` | 各指标开关，键为 `net_up` / `net_down` / `cpu` / `cpu_temp` / `mem` / `gpu` / `vram` / `gpu_temp`；缺省为显示 |

例如只显示 CPU 与内存：

```toml
[visible]
net_up = false
net_down = false
cpu = true
cpu_temp = false
mem = true
gpu = false
vram = false
gpu_temp = false
```

## 性能，以及为什么这么低

显示 6 项指标、每秒采样一次、Windows 11 且显示缩放 150%。悬浮窗大约消耗**每秒 3 毫秒 CPU 时间**——在任务管理器里基本看不到，远低于一个常见动画界面渲染一帧的开销。

- **数据不变就不重绘**：采集线程每采到一份新快照才发消息唤醒窗口（默认每秒一次），窗口只在此时重绘。没有持续渲染循环，也没有动画。
- **整个面板就是一张小位图**：背景和文字都合成到内存里约 160×180 像素的 32 位 DIB 上，再用一次 `UpdateLayeredWindow` 交给系统。
- **完全不用 GPU API**：界面不碰 OpenGL / Direct3D / Vulkan，因此只有 Microsoft 基本显示适配器的机器、虚拟机和远程桌面也能正常跑。

对比：同一悬浮窗此前的 `egui` / `wgpu` 构建工作集约 **125 MB**（OpenGL 后端）和 **420 MB**（WARP 后端），CPU 也高一个数量级。

## 打包与分发

- **单文件**：`cargo build --release` 产出的 `target\release\deskpulse.exe` 双击即可运行，也可以拷给别人；没有安装程序，也没有需要一起分发的配置。
- **应用图标与版本信息**：由 `build.rs` + `winresource` 从 `assets/icon.ico` 嵌入；`pwsh -File .\assets\make-icon.ps1` 可重新生成图标。
- **不依赖 VC++ 运行时**：`.cargo\config.toml` 对 `x86_64-pc-windows-msvc` 开启 `+crt-static`。
- **体积优化**：release 开启 `lto`、`codegen-units = 1`、`strip`、`panic = "abort"`。
- **无控制台窗口**：release 构建带 `windows_subsystem = "windows"`。
- **诊断模式**：`deskpulse.exe --dump` 不打开窗口，打印 5 次采样后退出。
